# Урок собственного применения: граница поиска при переносе кейса

## Итог адресной проверки

Прочитана независимая RELEASE-001/index-privacy-final.json у PL: в состоянии индексатора приватных файлов 0 до/после сверки; в Qdrant просмотрены 30271 записи с запросом только path, без текста/векторов. Префикс Cases и точный фильтр 1851 пути дали 0; записей без path нет. physical_cleanup_verified=true, infrastructure_mutated=false. Исправление закрыто только для затронутой области переноса, не для всех чужих проектов или всех возможных получателей данных.

Запрет новых включений подтверждён проектным правилом; прежние записи удалены существующим индексатором и их отсутствие проверено отдельно. Первоначальное попадание остаётся фактом истории, а не переписано как правильная подготовка.

## Исходное наблюдение — исторический срез до исправления

26.10.2026. Наблюдение сообщено PL Оркестратором при исполнении IMPLEMENT-001. На момент исходного наблюдения исправление и проверка очистки ещё были в работе; последующее подтверждение результата приведено выше.

## Ситуация и связь с целью

SMART переносился из отдельной клиентской папки внутрь PL Navigator, расположенного в D:/Project. Общий существующий codebase watcher автоматически индексирует проекты. Защищённый Windows ACL новой папки не предотвращает чтение индексатором под тем же владельцем. По сообщению PL часть Cases успела попасть в общий локальный индекс.

Значит, проверенные копия/ACL/Git/public ещё не доказывают требуемое разделение клиентских данных. Нужна проверка автоматических получателей данных до копирования в их область наблюдения.

## Требование и действие

Cases исключается из общего проектного поиска до копирования клиентских материалов. Проектное правило должно проверяться фактически. Уже созданные записи удаляются адресно существующим единственным индексатором в пределах проекта; не создавать новую базу, индексатор или глобальную переиндексацию.

Критерий результата — отдельно подтверждены запрет новых включений и отсутствие прежних записей нужной области. Одна ошибка codebase_read или запрет запроса не доказывают физическую очистку ранее записанных фрагментов. Содержимое клиента не выводится для этой проверки в отчёт/чат/память.

## Изменение методической проверки

PROTOCOL и C21 уточнены: граница закрытого кейса охватывает общий индекс наряду с Git, публичной сборкой, логами и Memora. Это конкретный выявленный риск текущей среды, не требование строить новую инфраструктуру защиты ради каждого пустого проекта.

Чужие проекты и прежние индексы за пределами данного переноса не очищаются автоматически. Перенос клиента и общий поиск остаются разными полномочиями. Дальнейший результат и пределы — по адресной независимой квитанции PL.

Независимая методическая рецензия roadmap_rules_review подтвердила точность границ текста, без чтения клиентского содержимого/индекса. Первоначальное нарушение сохраняется в истории; нельзя ретроспективно писать, что исключение действовало до первого копирования. Исправление принимается только по двум отдельным подтверждениям, указанным выше.
