# СТРУК на сайте через BetterDocs

Дата проверки: 21.10.2026, Europe/Moscow. Статус: предложение размещения и подготовленная карта переноса, без записи на сайт.
Основание: [R038](../../governance/sources/REQUEST-R038.md).
Исходники: [вики СТРУК](../../wiki/index.md), редакция wiki-draft-1.

## Рекомендуемое решение

Для первой версии использовать BetterDocs как читательскую базу знаний на WordPress. Содержательные исходники и история методологии остаются в YS Metodology; на сайт переносится читательская редакция. Изменения при редактуре нужно явно возвращать в канонический источник — автоматической двусторонней синхронизации сейчас нет.

Новая разработка плагина пока не обоснована: нужны статьи, иерархия, поиск, оглавление, навигация и обычные ссылки. BetterDocs предоставляет основные элементы базы знаний. Наши перекрёстные и обратные ссылки можно перенести как содержание статей.

Основания: [описание плагина и функций](https://wordpress.org/plugins/betterdocs/), [официальная инструкция MCP](https://betterdocs.co/docs/mcp-in-betterdocs/). Часть возможностей — отдельные базы знаний, встроенный глоссарий, расширенные связанные статьи и Git-интеграция — помечена разработчиком PRO. Для начала словарь и обратные ссылки могут оставаться обычными статьями/ссылками. Наличие этих PRO-функций в установленной редакции здесь не подтверждено.

## Что проверено на указанном адресе

- http://localhost:8080/wp-json/ отвечает 200; название — WordPress Lab, home/url — http://localhost:8080.
- http://localhost:8080/betterdocs/mcp: GET — 405 с указанием POST only; initialize через POST — 401, invalid or missing connection token.
- Защищённый ресурс объявляет Bearer header и OAuth scopes mcp/read/write. Проверен публичный маршрут /wp-json/betterdocs/v1/mcp/oauth/protected-resource.
- WordPress публикует тип docs и таксономии doc_category/doc_tag. REST-схема docs допускает draft.
- В публичной выборке docs — 0 статей; публичные категории и теги пусты. Наличие скрытых черновиков, приватных статей и иных объектов без авторизации неизвестно.
- Список MCP-инструментов, их точные схемы и право создавать черновики через MCP ещё не получены: авторизация не пройдена.
- Сервер на localhost — локальная лаборатория, не подтверждение состояния или доступности основного сайта.

Ни статьи, ни категории, ни настройки сервера не изменялись. Токены не получались и не сохранялись.

## Структура читательского раздела

Корневая категория — СТРУК. Внутри:

| Раздел | Содержание |
|---|---|
| Начало | Описание метода, первое применение, карта, вопросы |
| Метод | Связь функций и словарь |
| Пять функций | Ситуация, Требования, Решение, Управление, Контроль |
| Примеры | Обзор, повседневная жизнь, совместная работа, работа с ИИ |
| Об авторе | Автор методологии и редакция материалов |

На основном сайте нужен понятный вход в СТРУК: описание, начало применения, карта знаний и сведения об авторе. Точные адреса страницы входа и документов выбираются по действующей структуре сайта; глобальные permalink-настройки BetterDocs ради этого не меняются автоматически.

Штатный автор записи WordPress и автор методологии различаются. Перед публикацией нужно проверить отображение имени Юрия и подписи об авторстве, не приписывая ему без редакции каждый подготовленный ИИ текст.

## Карта и порядок переноса

[import-manifest.json](import-manifest.json) содержит 16 источников, постоянные id, предложенные уникальные slug, категории, темы, исходные SHA-256 и карту 209 локальных ссылок. Это транспортно независимый план; он не является готовым JSON для неизвестной схемы MCP tools/call или штатного CSV/XML-импорта BetterDocs.

1. Авторизовать предусмотренное BetterDocs подключение. На стороне WordPress: BetterDocs → MCP; для локального CLI/editor-подключения используется соответствующий раздел подключения, для OAuth — одобрение администратора. Секрет не нужно пересылать в чат или сохранять в Git.
2. Прочитать MCP tools/list, схемы операций, существующие документы/категории и доступность черновиков. Проверить скрытые дубли перед первой записью.
3. Сопоставить локальные id с WordPress id. Создать недостающие категории и 16 статей со статусом draft, без изменения существующих статей и чужих категорий.
4. Преобразовать Markdown в подходящее для редактора содержимое. Не переносить YAML, дублирующий заголовок H1 и служебные метаданные в тело статьи.
5. После получения фактических permalink заменить все относительные ссылки .md, включая якоря и обратные ссылки. Не угадывать будущие адреса по схеме /docs/slug/.
6. Прочитать сохранённые черновики через авторизованный интерфейс: сравнить заголовки и содержание, проверить категории, ссылки и отсутствие дублей. В редакторе/предпросмотре проверить таблицы, цитаты, заголовки, оглавление и навигацию.
7. Авторская редакция и публикация — отдельное действие над конкретными готовыми материалами. До публикации проверить поиск, навигацию и вид на телефоне в том окружении, которое станет публичным.

Если MCP не даёт нужного управления черновиками, резервный путь — штатный авторизованный WordPress REST API типа docs либо проверенный формат импорта BetterDocs. Новый сервер или плагин из-за ограничения одного транспортного способа создавать не требуется.

## Когда нужна собственная доработка

Сначала подтвердить реальный пробел на работающем разделе: например, нужные обратные ссылки должны строиться автоматически и учитывать переименования, необходимо особое представление версий или управляемая синхронизация источника с сайтом. Для такого пробела можно сделать ограниченную интеграцию, сохранив BetterDocs для обычных статей. Полная собственная вики оправдана только отдельными требованиями, которые готовая база не закрывает.

## Текущий следующий шаг

Пройти штатную авторизацию BetterDocs MCP для этой локальной лаборатории, затем получить точные схемы и загрузить подготовленную редакцию черновиками. Содержательная подготовка выполнена; запись в WordPress пока не выполнена из-за отсутствия авторизованного подключения.
